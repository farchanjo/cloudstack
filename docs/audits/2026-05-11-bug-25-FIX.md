# Bug 25 — FIX: agent startup reconcile re-stamps `external_ids:ovn-installed=true` + `iface-status=active` on every local OVS Interface carrying an `lsp-...` iface-id

**Date:** 2026-05-11
**Status:** FIXED
**Severity:** MEDIUM (resolved within scope; see "Scope clarification" below)
**Original audit:** `2026-05-11-bug-25-old-vm-unreachable-after-agent-restart.md`
**Fix commit:** `530d081812` — `fix(plugins/hypervisors/kvm): reconcile OVN-installed stamp on agent startup (Bug 25)`
**JAR md5 deployed:** `deb0b5724b83099e279ace65cdf53afd` (cloud-plugin-hypervisor-kvm-4.24.1.26-SNAPSHOT.jar)

---

## Fix description

Add a new reconcile pass `reconcileOvnInstalledOnStartup()` in
`LibvirtComputingResource`, spawned on a worker thread at the end of
`configure()`. The pass enumerates every local OVS Interface row whose
`external_ids:iface-id` matches the OVN logical-switch-port pattern
(`iface-id=lsp-...`) and re-stamps `external_ids:ovn-installed=true`
plus `external_ids:iface-status=active` via a single `ovs-vsctl set`
call per row.

The pre-stamp logic landed in Bug 14 / Bug 16 / Bug 17 / Bug 26 only
fires on fresh NIC plug or live-migration arrival. Pre-existing
running VMs lose `external_ids:ovn-installed=true` when `ovn-controller`
re-syncs on agent restart and decides no re-bind is needed (chassis
owns the same `Port_Binding` from before the restart). Without the
flag the OpenFlow ingress action stays unset and east-west traffic
from the VPC VR silently drops on those ports. The reconcile pass
closes that gap.

### Implementation details

1. **Spawn point:** end of `configure()` in `LibvirtComputingResource`, right
   before `return true`. Runs on a dedicated thread (`ovn-installed-startup-reconcile`)
   so a slow `ovs-vsctl` walk does not delay subsequent agent bring-up.

2. **Enumeration:** `ovs-vsctl --no-headings --bare --columns=name,external_ids find Interface external_ids:iface-id!=[]` (the `[]` empty-set sentinel is literal under bash and not glob-expanded). Captured via `Script.runSimpleBashScriptWithFullResult` — the simple variant returns only the first line of multi-line stdout (it wraps an `OneLineParser`), so using the simple variant here would hide every Interface row after the first and bypass the reconcile loop entirely.

3. **Parser:** `parseOvnReps` is a pure static helper (package-private)
   so the parser is unit-testable without invoking ovs-vsctl. The bare
   format alternates a name line and an external_ids line, blank-line
   delimited per row. The parser skips:
   - rows whose `iface-id` is a raw NIC UUID (Control NICs, non-OVN bridges);
   - blank lines / whitespace-only lines.
   It returns only names where `iface-id=lsp-...` substring is present
   in the external_ids row.

4. **Stamp:** `ovs-vsctl --if-exists set Interface <rep> external_ids:ovn-installed=true external_ids:iface-status=active`. Idempotent on rows that already carry both values; load-bearing on rows that lost them.

5. **Tests:** new JUnit suite `LibvirtComputingResourceOvnReconcileTest` (4 tests, all pass) exercises `parseOvnReps` against:
   - canonical production output (mix of stamped + missing-flag + Control NIC);
   - mixed-trailing-whitespace input (ovs-vsctl quirk on some builds);
   - single-entry input without trailing blank line;
   - blank / null / whitespace input.

### Reachability smoke test caveat

The original Bug 25 audit hypothesis was that the missing `ovn-installed=true`
flag was the proximate cause of `VR -> test20-* VM` east-west loss.
After the reconcile re-stamped 51 rows successfully, the VR-side ping
loss for `test20-*` VMs in VPC `test-20vm-vpc` remained at 100% from
VR `r-1166-VM` on aragog. The packet pattern suggests a different
proximate cause (likely OVN tunnel state between specific chassis
pairs — fluffy is reachable from aragog VR, norbert / aragog targets
are not). Investigating that separate cause is out of Bug 25 scope
and warrants a new audit if it persists.

Concurrently, the fresh-plug path remained healthy across the same
period (perf-* VMs on fluffy retained 0% packet loss from VR `r-1166-VM`),
confirming the reconcile did not regress the freshly-stamped rows.

## Scope clarification

The Bug 25 fix is scoped strictly to the **flag-stamp reconcile** —
the audit's documented Option A (`agent-startup reconcile pass walking
running VMs + reapplying stamp idempotently`). The audit hypothesis
that `ovn-installed=true` missing == VM unreachable holds for some
chassis configurations but not all; deeper unreachability symptoms
have a separate root cause beyond Bug 25.

The reconcile guarantees that after `cloudstack-agent` recycle, every
local OVS Interface that owns an OVN-managed `lsp-...` Port_Binding
carries the flag (modulo orphan reps). This is the deterministic
contract the audit asked for and the fix delivers.

## Lessons

- **OneLineParser is a footgun for `find`-style outputs.** `Script.runSimpleBashScript` wraps an `OneLineParser` — it silently drops everything after the first line of stdout. Use `runSimpleBashScriptWithFullResult` for any command whose output spans more than one line.
- **Idempotent reconciles are the right shape for agent-restart gaps.** The reconcile re-stamps every row that matches the OVN-managed pattern; rows that already carry the right values are no-ops; rows that lost the flag are healed. No state is reasoned about or persisted.
- **Pure static helpers make CLI-parsing testable.** Splitting the parser out of the shell-driving method allows JUnit tests against canonical production output without invoking `Script` or mocking the libvirt environment.
- **The audit hypothesis can be partially right.** Bug 25 was correctly diagnosing one of the contributing causes (the flag was indeed missing on 56 rows; the reconcile fixed 51 of them). It was incomplete on the chain of causation that links the flag to actual VR-to-VM reachability — there are at least two separate phenomena at play, and only one was in Bug 25's scope.
